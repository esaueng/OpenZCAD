Phase 3, desktop Keychain storage: the macOS app creates each device's signing (ECDSA P-256) and unlock (ECDH P-256) keys natively and keeps them in the Keychain as non-syncing generic passwords beside its refresh credential (`apps/desktop/device-keys`, Tauri commands `create_device_keys`, `sign_with_device_key`, `derive_with_device_key`, `delete_device_keys`); the WebView holds only public keys and a key id, and signs and unseals through the external keys `@openzcad/crypto` accepts. `keychainDeviceStore` keeps the IndexedDB device record with each private key replaced by its key id, rebuilds native handles on load, and removes Keychain keys no record references (a deleted or replaced device, a losing setup race). Browsers keep non-extractable WebCrypto keys. Evidence: the `openzcad-device-keys` crate tests (WebCrypto-computed vectors for public keys, ECDH and P1363 signatures; failure cleanup; id and peer validation), run on Linux by the dependency-audit workflow; the end-to-end "desktop Keychain device keys" case in `test/e2ee-account-keys.test.ts` (setup, unlock through the host's ECDH, a device-signed recovery-key replacement, forget); `apps/web/src/lib/e2ee/keychainDeviceKeys.test.ts`. The Keychain calls themselves run only on macOS; the manual Apple Silicon workflow was not dispatched, by the maintainer's choice.
