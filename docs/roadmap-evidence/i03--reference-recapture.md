Stored-unit conversion phase 4 (plan `docs/plans/i03-stored-unit-conversion-plan.md` §3.2, §6 steps 2–3, §7 row 4): `computeConversionReferenceMap` in `packages/kernel-adapter/src/units-reference-recapture.ts` re-captures every persisted topology identity of a converted document by rebuilding, never by scaling witness integers. The source document is built cold and each reference lookup is recorded with the entity it resolved to; the converted document is built cold with every lookup replaced by the unique entity whose witness is the recorded one scaled by k within two quanta of the coarser unit, carrying the same lineage name (imported-STEP hash names compared by family) or, for a legacy hash-only pick, none. Schema-v5 face and edge references, legacy `faceHash`/`edgeHashes`/`oppositeFaceHash` and emboss hashes (in their original scheme), and sketch `regionFingerprint`/`profileId` are covered through one hook seam (`reference-recapture-slot.ts`) in the three resolvers. The result is a map keyed by JSON pointer; `listConversionReferenceSites` and the pure `applyReferenceMap` (`packages/document-core/src/units-reference-map.ts`) apply it without a kernel for phase-5 replay. A verification build of the applied document must resolve every identity, propose no repair the source build does not, and match the source per body (bounding box within 1e-6 + 1e-9·scale, volume ×k³ and face area ×k² at 1e-6, face/edge/vertex counts, consumed/exportable flags, exportable set and warnings). Missing, ambiguous, conflicting, never-resolved or never-looked-up identities and any oracle mismatch refuse, naming the node and field. Parity property (`test/parity/unit-conversion.spec.ts`): of 13 documents (parity scenarios, the visual-selection demo, the import-modeling corpus) 11 convert to cm and to inch and round-trip back to identical witnesses; Scissors refuses in phase 2 (assembly) and `boolean-on-nurbs-import` is pinned as a kernel refusal (its B-spline faces measure volume 7.5e-6 and area 0.8% differently at another scale). The b-unit STEP files keep their physical size through import, conversion and export. No command, UI or schema change.
