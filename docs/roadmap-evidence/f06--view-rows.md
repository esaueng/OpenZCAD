One configuration per drawing view (schema v89, built on v81 with v82, v84, v85, v87 and v88 claimed by D02/D03, v83 by M17 and v86 by F06 slice 4a; [design](docs/plans/configurations-design.md)): a base drawing view may name the configuration row it draws (`configurationId`, set from the view's settings in Draw and undone like any drawing edit); every view folded, cut, detailed or seen square from it draws the same row, and says so. The view's bodies are tessellated and sectioned from `documentForConfiguration` while the document's active row stays the model being edited; tessellations, section planes and projections are keyed by the row and the model content, so a row view never shares geometry with the active row's and is drawn again when that row can have changed, while views on the active row keep exactly their keys. A derived view cannot name its own row, a view cannot name a row the table does not hold, a row (or the whole table) a view shows cannot be deleted, and the choice is validated on load and in history and gated to v89. Evidence: `test/configuration-views.test.ts` (set, undo, clear and refuse a view's row; deletion refused; validation and the v89 gate; derived views drawing their source's row; projection keys apart from the active row and following the model content) and `test/e2e/configuration-views.spec.ts` (a front view switched to Large draws 45 mm wide at 1:1 and its projected top view follows, while Build still edits the 20 mm Small; back on the active row both draw 20 mm).
