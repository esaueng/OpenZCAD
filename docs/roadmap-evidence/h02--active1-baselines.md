2026-11-15 Active 1 first-edit-after-reload baseline, three quiet-host runs on main `90c163c62` with Remus 2026.1.141, on a Ryzen 5 5600 with a discrete Radeon RX 6600 through Vulkan ANGLE. The machine has no integrated GPU, so that wording in Active 1 maps to this discrete GPU here; a real integrated-GPU device remains unmeasured ([record](docs/performance/2026-11-15-active1-baselines.md)). With the persisted session restored instead of replayed, reload → exact ready is 648 / 461 ms on the drilled (15 features) and lettered (31 features) holders. The first edit after a settled reload is 556 / 260 ms against a warm 435 / 146 ms, and an edit typed during the reload is 854 / 577 ms. Every run falls within 5% of its median except the lettered holder's first edit (−9% / +7%) and reload (−4% / +7%). Budgets (medians): reload 1,000 / 700 ms, settled first edit 850 / 400 ms, edit during reload 1,300 / 900 ms, plus the retained within-run ratio (first edit ≤ 1.5 × warm + 250 ms). `node scripts/measure-active1-baselines.mjs --check` reruns and enforces them (`scripts/active1-budgets.mjs`; probes record renderer, load and memory per sample). Contributors: after a session restore the lettered holder's first edit replays 27 of 31 features (138 ms of history against 60 ms warm), because the restored session lacks the independent-reuse state until one edit has run; the drilled holder replays all 15 features on every edit. The large-pattern preview baseline is also in this record: a 10 × 10 grid on a public reconstruction of QA's ×50 bar previews in 7.5 s, against a budget of 10 s that gates M02; `fuseAll` is 91% of the frame's kernel time. Not measured: the hammer-holder STEP behind the 18–31 s report. On this pin its verified "Parameterize holder and text" recipe fails exact-geometry preflight, so it has no parameter to edit.
