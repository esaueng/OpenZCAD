Repeated curved patches: on an invented slotted block, whose R5 bore two slots split into three patches beside an uninterrupted R5 control cylinder, resizing the middle patch through the radius drag's `resize-through-hole` route or the generic `resize-cylindrical-face` route changes only that patch. Its radius and the volume change π(r² − R²)·8 match in closed form, the exported solid passes strict validation, and the siblings' fingerprints, trims and the control's topology stay unchanged. The patches carry no lineage name at this pin (split carriers remain K05), so the edits stay pinned by hash. Moving either slot rebuilds the patch and refuses with the typed `reference_missing` repair prompt and the unedited body. Lengthening the block keeps the edit on the same patch. Undo, Redo and reopening reproduce the same faces, and a patch drag never routes to the bore primitive. Half-turn variants (a broken-out trough, half-round ribs) refuse with typed `unsupported` direct-edit reasons and leave every patch in place. One open defect is pinned as an expected failure: a second drag on a patch folds into the history tip whenever the tip resized a coaxial sibling to the same radius, which moves the sibling instead (`cylinderResizeFold.ts`; `test/repeated-curved-patches.test.ts`).
