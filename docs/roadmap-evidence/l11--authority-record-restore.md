Issue #1704, a withdrawn authority record: an account that returns no authority record for a project one of its devices already verified is still refused, with every pin kept, whether the record was erased or is only withheld. Where the device pinned this account, under its current identity, as the project's owner, the refusal now names the way back, and Settings › Encryption › Advanced encryption settings › Encrypted project recovery lists the project with a Restore record action. After the owner confirms in plain words, a certified device re-checks its pinned record under the account's keys and saves it again one sequence on (the same roots, key epoch and GroupInfo); the Worker stores a restoration (`restoreMissing`, owner only) only while the account holds no record for the project, never in place of one, and other devices accept it against their own pins like any newer record. An identity that was set up afresh, another account's project, a read-only device and a pin that no longer opens restore nothing. No migration.
