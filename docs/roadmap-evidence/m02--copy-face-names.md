Named faces on boss and cut copies (no schema change). A feature pattern
now names each repeated boss's or cut's copy faces after the faces of the
feature it copies, `pattern.face.instance.<label>.source.<feature>.<its
name>`, as slice 1 named hole copies' bores. A copy's face takes the name
only where exactly one face of the result is the original's moved by the
copy's placement: the same kind of surface on the moved carrier, with the
moved centroid and the same perimeter, within a few quanta of the
witnesses' rounding. A face the body truncates differently (a copy running
off the plate's end, a boss merging into another) is not congruent and stays
unnamed, as does a face two copies would both claim, so a name always means
the copy's own face. The original keeps its names. Evidence:
`test/pattern-copy-face-names.test.ts` (a boss row and a pocket row: every
face of copies 1 and 2 named after the original's, each 25 further along;
a pocket row whose last copy runs off the plate leaves that copy unnamed).
