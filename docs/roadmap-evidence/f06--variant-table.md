Variant table and active row (schema v72, built on v70 with v71 claimed by M17; [design](docs/plans/configurations-design.md)): Parameters gains a Configurations table whose rows are named configurations and whose columns are parameters, feature suppression, body visibility and material. The table is dense and exactly one row is active. The active row's parameter and suppression values are the model's own, so rebuilds, panels and exports read it unchanged; switching rows copies the live values back into the row being left and writes the new row into the model as one undoable step, and a parameter or suppression cell of the active row edits the model directly. Bodies the active row hides are hidden and left out of STEP and mesh exports where an L05 off switch hides them (the exact adapter's export filter included), and the Inspector's mass properties use the active row's material. A row the model cannot take is refused naming the row; the section, its history and its commands are validated on load and gated to v72; diagnostic reproductions replace row names. Evidence: `test/configurations.test.ts` (dense table, activation round trip keeping edits in the row left, hidden bodies, refusals, rename/delete, export document for another row, storage gate and validation, undo/redo/replay and history validation, diagnostic redaction, exact rebuild of each row with export filtering), `ConfigurationTable.test.tsx` and `test/e2e/configurations.spec.ts` (build a table, switch, undo/redo, reload).
