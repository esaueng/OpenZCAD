Delivered as Phase 1 of the [design note](docs/plans/l14-agent-api-design.md): `openzcad-mcp` (`apps/agent-bridge`), a local stdio MCP server on user-granted `.openzcad` files, built on the transport-free tool core `@openzcad/agent-api`. It exposes the canonical document (`get_document`), the assistant's exact digest (`get_digest`), the schema-constrained patch vocabulary (`get_patch_schema`; `CAD_PATCH_JSON_SCHEMA` is also the patch tools' input schema) and exact preflight (`preflight_patch`), and `apply_patch` re-runs `parseCadPatchProposal` against the digest and `preflightCadPatch` on the exact kernel before committing one `CommandManager` transaction (one ADR-023 undo entry, "Apply agent patch"). Authority is the launching OS user: no listener, no network (a guard replaces the web network globals), project files must be owned by and writable only by that user and sit in a folder others cannot write (sticky folders excepted), rechecked on every read and write with the path required to resolve to itself and the file opened without following links, ciphertext is refused by shape, and tools address projects by alias or id only. Scope (`read`/`preflight`/`edit`, default `preflight`) is fixed on the command line; rate limits are 120 reads and 12 exact-kernel calls per minute (lower-only flags), one kernel job running and one waiting, a 120 s cooperative derivation deadline read from the clock (so a kernel call that holds the event loop cannot slip past it) and a commit claim that refuses to write once the deadline has passed and is never reported as timed out after writing, and a refusal of any patch whose undo entry ADR-023's history budget would drop, 2 MiB request lines and a 4 MiB document answer; writes are fenced by stored-revision hash and document version and replace the file atomically. E2EE: plaintext stays on the user's disk and goes only to the agent host the user configured; nothing reaches the server. Regression evidence: `packages/agent-api/src/agent-api.test.ts` (protocol, scope, limits, gate, transaction and undo), `test/agent-bridge.test.ts` (grants, ciphertext refusal, atomic write and conflict fence, network guard) and `test/agent-bridge-e2e.test.ts`, which spawns the real server over stdio under a network tripwire and drives a real edit: digest, exact preflight of a 40 → 60 mm width change (24 000 → 36 000 mm³), refused and stale applies leaving the file byte-identical, the apply, an importer-accepted file whose exact rebuild measures 36 000 mm³, and one undo back to 24 000 mm³. The live bridge to an open workspace (loopback relay or desktop shell) remains a separate owner decision (design note, Phase 2).
