Gear edge names (after partial-span teeth, PR #1389; no schema change, no kernel change): every gear body now names its edges as well as its faces, so a fillet or chamfer on a gear edge follows later gear edits instead of being pinned to an edge hash. An edge is named from the two faces it lies between, `gear.edge.between.<face>|<face>` with the two face names in string order (`gear.edge.between.gear.face.cap.end|gear.face.collar.end`, `…gear.face.bore|gear.face.cap.start`, `…gear.face.collar.start|gear.face.shoulder.start`), the pair read from the built solid's own topology and never from position or output order; it applies to new spur, helical, herringbone, bevel, worm and enveloping gears and to teeth cut on a body, whose carried faces count by their carried names (`packages/kernel-adapter/src/exact-gear-edges.ts`, [ADR-013](docs/adrs/ADR-013-persistent-topology-lineage.md) M14 amendment). Tooth edges are named the same way rather than left out, so they follow the tooth index of their faces (`…tooth[3].flank.plus|…tooth[3].tip` is tooth 3's edge at any tooth count that has one): the rule is one rule and costs nothing extra. Where one pair of faces shares several edges each is `….piece.<i>.of.<n>`, ordered along the gear's axis, the count part of the name; pieces at one height publish no name, because around the axis no origin survives every edit (the x direction is a parameter and the blank can be turned), so an angular count could hand one piece's name to its neighbour. The one case found is a collar's seam cutting the smooth arc it shares with a flush keep-diameter tooth tip in two (four unnamed half-arcs on a two-collar gear, edges no blend applies to). Edges with an unsupported witness and seams publish no name either. Face names and hashes are unchanged: compared against main for a bored spur, helical, herringbone, bevel, worm and worm-wheel gear and for whole-face and partial teeth of both fits and anchors on a boss, every face name, face hash and edge hash is identical; only edge references are added (482 of a bored 20-tooth spur's 483 edges, the other its bore seam). Resolution is unchanged and stays strict: a stored edge name the body no longer publishes refuses as `reference_missing`, never rebinding (teeth run up to an end remove its collar and that rim; fewer teeth remove the higher tooth indices), and a hash-only edge pick stored on a gear before this takes the existing all-or-nothing upgrade to its name on the next build. Evidence: `packages/kernel-adapter/src/exact-gear-edges.test.ts` (CI unit smoke selection: pair naming whatever order faces and edges are listed in; an index only for several edges of one pair, counted along the axis from either end; no name for pieces at one height, without a frame, beside an unnamed or twice-named face, for seams or for a closed spline), `test/gear-edge-lineage.test.ts` (smoke selection, exact kernel: every pickable edge of a bored spur, of whole-face teeth and of set-module partial teeth named once, each name equal to the pair of faces the kernel's adjacency reports; the same names and hashes on a second kernel instance and after a span edit and back; keep-diameter partial teeth named but for the four smooth seam-cut half-arcs; a fillet and a chamfer on the top cap's rim, teeth anchored at the start and at the end, each still taking exactly the analytic volume off the Ø22 rim after a length, an offset, a length-and-offset, a tooth-count (20 → 18), a module (0.9 → 0.8) and a blank-height (12 → 14, the blend following to z 14) edit; a fillet stored by hash alone resolving, being offered its name, and with it following an edit that loses the hash-only one; the rim's fillet refusing by `reference_missing` with the gear passed through unrounded once teeth reach that end or run the whole face, and resolving again when the collar returns) and `test/gear-edge-lineage-extended.test.ts` (full suite: a fillet on the shoulder's rim, `collar.start|shoulder.start`, following length, offset, tooth-count and height edits at both anchors with the blend at the shoulder's new height; a fillet at one tooth space of a keep-diameter shoulder, `root[3]|shoulder.end[3]`, through a span and a tooth-count edit at both anchors; a fillet and a chamfer on a whole-face gear's bore rim through tooth-count, module, face-width (its cap drag) and bore-diameter edits; a tooth-tip edge found by its tooth from whole-face teeth to part of the face and back, refused by `reference_missing` at 18 teeth and found again at 22). Kernel limits, not naming ones, recorded as found: it refuses a chamfer on a shoulder's rim and at a split shoulder's tooth space ("could not be chamfered on this body"), refuses both blends on a cap's edge at one tooth and on a narrow (1.1 wide) shoulder's rim, and builds a tooth-tip fillet on some teeth and spans only, so those cases are fillets and the tooth-tip case asserts that the edge is found (built, or the kernel's own geometric refusal, never a lost reference). Still open, unchanged from #1389: a reference to the body's part of a split end cap (`gear.face.cap.*.body`) refuses by name once the caps rejoin, and the one edge beside that part shares it; following it needs rejoin provenance this PR does not add. With edges named, the row's remaining promise ("every face named from its kernel role so later fillets and holes survive edits") holds for fillets and chamfers as it did for holes and datums, and both listed M14 items (the meshing-pair helper, PR #1373, and partial-span teeth, PR #1389) have landed, so M14 is Complete.
