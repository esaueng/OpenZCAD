Slice 2, read-only preview. Revisions › Preview on any stored save point that is not the current one builds that save state exactly (`geometry.syncOnce`, the same path as the assistant's exact preview) and shows it in the viewport in place of the project, behind a notice in the workspace's notice row: "Previewing “name” · Saved … · N bodies · read only", with Restore, Branch and Close preview. The row being previewed is marked in the list. Nothing is written: the project, its undo history and its save points are untouched, and every edit is refused ("A saved version is open for preview — close it to edit") until the preview closes; anything that replaces the preview geometry ends it. Restore and Branch from the notice close the preview first and then run the ordinary restore and branch, so they meet the project's own guards; a seat that cannot edit sees no Restore. The save state is read from this device first and then the account; on an encrypted project the account read is ADR-024's historical read (`encryptedProjectStore.loadRevision`: accepted only as the pinned head or an ancestor in the trusted chain, never moving the pin), so a preview never moves this browser's view of the project. Evidence: `SaveStatePreviewNotice.test.tsx`, `RevisionsPanel.test.tsx` (Preview offered only for a stored, non-current save; the previewed row marked) and the CI smoke case `test/e2e/save-state-versions.spec.ts` (a box saved, a cylinder added; preview draws one body while the project keeps two, Undo does nothing while previewing, Close shows two again, Restore from the notice leaves one).
