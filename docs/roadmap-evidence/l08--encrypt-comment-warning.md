Comments when a plaintext project is encrypted (plan decision 5, confirmed by the owner on 2026-11-17). Encrypted comment logs cannot carry a plaintext project's comments yet, so the migration's cutover deletes them with the rest of the plaintext. The deletion is never silent. Before anything is staged, the migration engine counts the project's comments through `GET /api/projects/:id/comments`; a server without comment storage counts none. While the project holds more comments than the owner has confirmed, the run stops on it. That covers a manual Encrypt projects run and the automatic default-on migration alike. Settings › Encryption › Encrypt existing projects then shows the row as "Waiting for your confirmation", says "Encrypting deletes N comments", and offers "Delete N comments and encrypt". A project that gains comments after the confirmation asks again. The "What changes" notes say comments are deleted on encryption. Evidence: `test/e2ee-project-migration-engine.test.ts` (nothing staged and both comments kept until confirmed, a confirmation for fewer asks again, the confirmed run cuts over and deletes them); `ExistingProjectEncryption.test.tsx` (the row names the count, offers no cancel while nothing is staged, and passes exactly the confirmed count to the engine); and the CI smoke case in `test/e2e/encrypted-migration.spec.ts` (two comments, the confirmation, then encrypted with no comments left).
