Phase 1e, document validation in the browser: `assertStorableDocument` (`@openzcad/document-core`) runs every content check the account and the collaboration room made (structure, envelope, schema version, revision and checkpoint history, undo history, sketch provenance, reference dimensions, text budget, drawing, Objects folder and reference-image sections, content schema, imported STEP and mesh sources, normalization first, so older documents migrate as they always have on load, then the content checks on the result). The browser runs it before every account write (`splitProjectStorageUpload`), before every room submission, named room save and kept version, and on every document the room hands it: a version it cannot open becomes a refusal that keeps the last good version (state frames drop the document, acknowledgements drop the echo, merge bases are dropped), while a newer client's document still asks the user to update. Autosave treats such a refusal as permanent for that edit (`refused`, never `offline`) and resumes with the first newer edit that passes. The server checks are unchanged in this slice; later slices validate account loads in the browser and then remove them. Evidence: `test/storable-document.test.ts` (including older documents that must still open), the browser-refusal case in `test/cloud-project-autosave.test.ts`, and the refusal and no-publish cases in `apps/web/src/lib/useCollaboration.test.tsx`.
