One configuration per assembly instance and per model view (schema v90, built on v89; F06 first claimed v79 and then v86, which v80, v81 and v89 overtook; [design](docs/plans/configurations-design.md)): an assembly component may name the configuration it shows (`configurationId`, set from the part's details in Assemble and undone like any assembly edit), and the View workspace has its own Configuration picker above its parts. Each named row is built on its own from `documentForConfiguration` and drawn in place of the active row (a part keeps its placement; a body the part's row suppresses or hides is not drawn), while the document's active row stays the model being edited; rows rebuild only when the geometry changes, not when a part moves. A component cannot name a row the table does not hold, a row a component shows cannot be deleted, and the choice is validated on load and gated to v90. Per-drawing-view configurations follow after the D03 drawing work lands. Evidence: `test/configuration-instances.test.ts` (set, undo, clear and refuse a component's row; deletion refused; storage validation and gate; which rows build; building a row without touching the document), `AssemblyPanel.test.tsx` and `ViewModeRail.test.tsx` (the pickers), and `test/e2e/configuration-instances.spec.ts` (a part drawn 45 mm wide as Large while the model stays Small, through undo, redo and reload; View showing Large without the lug, and Build still editing Small).
