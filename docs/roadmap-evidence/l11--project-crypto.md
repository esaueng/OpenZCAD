Phase 4 slice 4-2, crypto additions for project data (package only; no app, server or D1 change): `@openzcad/crypto` appends the `project-info` and `key-archive` project envelope kinds (codes 5 and 6, 1 MiB ceilings; the first four codes are unchanged), adds the `rejoin-psk`, `archived-project-key` and `previous-account-key` AES-KW wraps, renames the header's former roster-entry slot to `epochBindingHash` with no wire change and fills it from `epochBinding(projectId, keyEpoch, epochAuthenticator)`, and adds the version log (`versionLogRecord`, the `OZV` record codec and `verifyVersionLog`, which refuses gaps, non-increasing versions, falling key epochs, broken parent links, bad signatures and a missing pin with typed reasons), `verifyAuthoredEnvelope` (certified author device, revoked devices only within their per-project cutoff) and strict JSON body codecs for documents (with signed revision version hashes), project info and key archives that keep header blob ids equal to body references. AES-KW unwraps now re-wrap and compare, so an engine that skips the RFC 3394 integrity check (Playwright's Windows WebKit) still refuses a wrong key, context or tampered wrap. ADR-024 records these in its 2026-10-24 amendment. Evidence: `packages/crypto/src/version-log.test.ts`, `bodies.test.ts`, the new vectors in `vectors.test.ts` (existing vectors unchanged byte for byte), the project-data and non-verifying-engine cases in `wrap.test.ts`, and the log-record and body cases in `fuzz.test.ts`.
