Whole-worker retention over a sustained session is bounded. A checkpoint restore retires arena slots as tombstones that are never reused, and the replay-work recycle counts features, not slots: 300 edits of the public filleted union left 343k retired slots, grew WASM linear memory 32 → 270 MB and the checkpoint estimate 1.2 → 157 MB (past the 128 MiB admission budget), and slowed one-feature edits about 47 → 58 ms. The adapter now classifies arena wear from the stats checkpoint admission already reads (`historyArenaWear`): a worn kernel (65,536 retired slots, four times the live ones) is compacted by the idle warm-up into a fresh kernel, which the worker now schedules for every live project (it stores nothing), and an exhausted one (262,144) is recycled before the next build (`recycleReason: 'arena-retention'`); a worn kernel is never persisted. Same session after: five idle compactions of about 220 ms, WASM memory plateau 102 MB, estimate ≤ 32 MB, edits flat at 43–47 ms, Node heap flat ([record](docs/performance/2026-11-20-sustained-session.md); `test/sustained-session-retention.test.ts`, `apps/web/src/worker/geometryWorkerSessions.test.ts`). Browser-worker heap on target hardware remains owner-pending.
