Browser coverage adds Firefox. `pnpm --filter @openzcad/mls test:browser` runs the MLS scenarios in a real module Worker in Chromium, WebKit and Firefox (55/55 steps in each; `-- --chromium-only` runs Chromium alone). New `pnpm --filter @openzcad/crypto test:browser` runs `packages/crypto/browser/scenarios.ts` on each engine's own WebCrypto and web streams in Chromium, WebKit and Firefox: chunked, incremental and streamed envelopes and content blobs (gzip and none, tampering, truncation, a gzip bomb), AES-KW and AES-GCM wraps, seal and open, project-envelope, version-chain, device-list, approval-grant and identity-transition signatures, the external-key seam (`ecdsaSign`, `ecdhDeriveBits`) and the fixed vectors, byte-identical in every engine; `test/crypto-browser-scenarios.test.ts` runs the same steps in Node under `pnpm test`. Both browser runs need `pnpm exec playwright install chromium webkit firefox` and stay out of `pnpm test`. Firefox 155 passes every step of both (26/26 crypto); no Firefox-specific defect was found. Playwright's Windows WebKit build does not enforce the AES-KW (RFC 3394) integrity check, returning a zeroed key for a wrong KEK or altered bytes, so 2 of its 26 crypto steps fail on Windows; Chromium and Firefox reject both.
