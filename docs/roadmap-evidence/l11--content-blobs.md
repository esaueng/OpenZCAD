Phase 4, slice 4-6, encrypted content blobs with HMAC dedupe: D1 migration `0034_e2ee_content_blobs.sql` adds `e2ee_content_blobs` (per project and blob id: kind, opaque object key `e2ee/<projectId>/<blobId>`, ciphertext bytes, an optional dedupe tag unique per project, and a committed or deleting state), `e2ee_version_blobs` (the blob ids each accepted version's header names, the reference count garbage collection reads) and an `e2ee_blob_kind` marker on `upload_sessions`, with triggers that refuse a reference to an uncommitted blob, a claim on a blob a retained version names, the removal of an unclaimed blob, any change to what the Worker accepted, and an encrypted session becoming an artifact; blobs share the artifact quota and reservation accounting of migrations 0017 and 0022, counting ciphertext, and carry erasure fences. `apps/web/worker/e2eeContentBlobs.ts` serves `/api/e2ee/projects/:id/blobs` (`GET ?tag=`), `blobs/uploads` (POST: an upload session for the blob id the browser proposes, the same one on a retry, or the committed blob), `blobs/:blobId/finalize` (POST) and `blobs/:blobId` (GET ciphertext), behind the key gate, `E2EE_PROJECTS_ENABLED`, migrations 0031–0034 (503 without them), the session/erasure write predicate, owner only and format 2 only; the bytes go up through the ordinary single-part and multipart upload routes, and finalize reads only the stored object's head (`parseEnvelopeShape`, new in `@openzcad/crypto`) to require a content blob of the session's kind named by the session's id, within its kind's ceiling, exactly `envelopeBodyLength` long and, uncompressed, its whole declared size, discarding a refused object with its session. Document versions now accept header `blobIds` only when every one is a committed blob of the project, recorded in the version's own batch; after each save, garbage collection drops references of pruned versions and removes blobs no retained version names once they are a day old (`E2EE_UNREFERENCED_BLOB_GRACE_MS`), and a dedupe lookup offers only blobs it would keep for half that again. Closing 4-1's gap, plaintext upload sessions, artifact finalize, listing, metadata and downloads refuse format-2 projects, and an encrypted session refuses a plaintext project; purge and erasure remove blobs with their projects. In the browser, `apps/web/src/lib/e2ee/encryptedContentBlobs.ts` is `archiveArtifact`'s encrypting transport for STEP sources, mesh payloads and reference-image pictures: an `assetDedupeHash` tag under the project's dedupe secret (from the current key archive, `dedupeSecretForProject`), reuse of a tagged blob only when this page holds its reference for the same plaintext checksum, otherwise `encryptContentBlobStream` (`createContentBlobWriter`) under a fresh key, the upload session and finalize with the tag; the artifact id the document records is the blob id. Writes put the reference of every blob the document names in the body, the decode worker derives the header's `blobIds` from that list and `checkBlobReferences` runs on every write; verified reads register their bodies' references (`blobReferences.ts`), the page decrypts a document's sources in the decode worker before geometry workers rebuild (`preloadEncryptedImportSources`), and `exactSourceResolver.ts` and backups read blobs the same way. 4-5's refusal of imports, meshes and reference images is lifted; embedded payloads, original mesh files, thumbnails, exports, measurements and view state stay on the device. Ordinary uploads, imports, purge and erasure do not depend on 0034; the flag stays off and the migration needs its own authorization before it reaches production.
