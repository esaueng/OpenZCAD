Slice 11, iOS universal app: `apps/ipad` builds for iPhone and iPad (`TARGETED_DEVICE_FAMILY = 1,2`, same bundle identifier, display name and signing). The iPhone allows portrait and both landscapes but not upside down, shows its status bar so `env(safe-area-inset-*)` applies, and seeds `openzcad.layout:v1` to `compact` at document start on the private origin when it is unset, never replacing a chosen value; the iPad keeps all four orientations and a hidden status bar. `scripts/run-ipad-simulator.mjs` falls back to the newest installed iPad when "iPad Pro 11-inch (M4)" is missing, and `--iphone` (or an iPhone name or UDID in `OPENZCAD_IPAD_SIMULATOR`) targets an iPhone; `test/ipad-simulator-selection.test.ts` covers the choice. Native `WorkspaceIdiomTests` cover the idiom decisions, the Info.plist orientation keys and the seed (once, origin-scoped, storage failures tolerated). `node scripts/run-ipad-simulator.mjs --test` passed on an iPad Pro 11-inch (M5) simulator (10 unit and 3 UI tests) and with `--iphone` on an iPhone Air simulator (10 unit and 2 UI tests; the touch sketch smoke is skipped on the phone until slice 6), both iOS 27.2. On the phone the smoke reaches header actions through the command bar, because the full layout's header sits under the status bar until slice 2. Simulator results do not establish real-iPhone memory or GPU budgets; those remain device evidence under [W01](#w01).
