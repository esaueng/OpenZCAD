Phase 4, slice 4-4, solo MLS groups, the server sequencer and the project key store: D1 migration `0032_e2ee_project_groups.sql` adds `e2ee_project_groups` (one group per project: generation, key-epoch base, current epoch, the newest GroupInfo and its epoch, and the signed epoch-zero GroupInfo every join archive starts from), `e2ee_mls_commits` (primary key `(project_id, epoch)`, so the first Commit for an epoch wins; kinds `commit` and `external`; immutable except that erasure clears the sender), `e2ee_project_leaves` (leaf keys and their version-2 certifications), `e2ee_project_keys` (per user and key epoch, the project key and the rejoin PSK AES-KW-wrapped under a named account key, decision D1) and `e2ee_key_archives` (one signed `key-archive` envelope per key epoch), with project and user cascades, erasure fences on every insert and update, and a trigger that keeps the sequencer from moving backwards. `apps/web/worker/e2eeProjects.ts` serves `/api/e2ee/projects/:id/` `mls/group-info` (GET; POST creates epoch 0), `mls/commits` (POST; GET `?after=`), `mls/leaves`, `keys` (the caller's own wraps only) and `keys/archives`, behind the key rollout gate, the off-by-default `E2EE_PROJECTS_ENABLED`, migrations 0031 and 0032 (503 without them; `projectsEnabled` in `/api/e2ee/config` now also needs 0032), the session/erasure write predicate, owner only (members 403, others 404) and format-2 projects only; a Commit, the `epoch = epoch + 1` update fenced on the epoch it names, the new GroupInfo, its wraps, its key archive and, for an external Commit, the joining leaf land in one D1 batch or not at all, a late Commit gets 409 `EPOCH_TAKEN` with the winner (also when two submissions for one epoch both passed the read and the second batch finds the fence moved or fails on the Commit log's primary key), and the sender must be a device the caller's newest device list certifies (a read-only approved device holds no leaf, decision D4). In the browser, `apps/web/src/lib/e2ee/projectGroups.ts` creates the group (leaf certified from epoch 0; safe to retry: a project that already has a group is joined, local state whose creation never reached the server is discarded through the per-project `MlsProjectSessions.discardSession` / `MlsSessionStore.deleteSessionIfCurrent`, a lost answer counts as created, and a device that lost the creation race joins the winner's group by external Commit; in-group state the server's leaf registry never saw is never caught up or committed from), joins an owner's own device by external Commit with the newest account-wrapped rejoin PSK and a join archive decrypted from the key archives (decision D3; the leaf certified from the group's current epoch, a stale leaf of the same device replaced), commits with the new epoch's exports read from a confirmed sealed copy of the pending session (`MlsProjectSessions.previewPending`), rebases a Commit or rejoin that lost its epoch, catches up in order, and recovers a crash by confirming a stored pending Commit equal to the server's winner, discarding it otherwise and resending one nobody ruled on; key epochs are the group's base plus its MLS epoch (decision D10), and older keys open from the account wraps (through `openAccountKeyChain` for older account keys) or a later archive, cached in `unlockedProjectKeys.ts` until key-session teardown.
