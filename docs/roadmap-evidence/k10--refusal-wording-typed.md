Three refusal-wording fixes, read from typed fields, never kernel prose. A
Mirror whose source body has no shape at its place in the history (it is
suppressed, or its feature failed) now throws the adapter's typed
`mirror_source_unavailable` (`reference` / `invalid_input`) instead of the
bare "Mirror target is unavailable.", and the web words it from the code,
including after a refused body's name in the multi-body Mirror bar
whatever the feature is named, since a typed code is now read before the
text rules, and History's failing-step card and the Resume dialog word a
refusal by its typed record as the command bar does
(`test/mirror-several-bodies.test.ts`, `refusalLanguage.test.ts`,
`InPlaceCommandBar.test.tsx`, `FeatureHistoryPanel.test.tsx`,
`ResumeHistoryDialog.test.tsx`, `historyResume.test.ts`). Every "smaller sizes failed too" clause in
the fillet and chamfer diagnosis (`neighbor-faces`, `unknown`, `closed-rim`,
`ends-on-blend`, `trim-face`) now needs a smaller rung that actually ran and
was refused with the requested size's own typed code (#2201's rule); an
empty ladder, rungs refused with another code, and rungs discarded or thrown
without a code get the same cause without the claim
(`edge-modifier-fallback.test.ts`, Cell 4b's 1.5e-9 mm case in
`test/boolean-role-correction.test.ts`). An in-place value refusal no longer
repeats the tool's last word ("Solid offset offset", "Draft draft", "Gear
teeth teeth"; `valueName.test.ts` scans every tool value). A blend refusal's size in exponent notation takes its unit after the
whole number ("1.5e-9 mm", not "1 mm.5e-9"; `sizeRefusal.test.ts`).
