Runouts and tapered pipe threads (schema v57, on Remus with esaueng/remus#1698 and #1701). A thread end can now run out (`runoutStart` / `runoutEnd`, the kernel's `{ kind: 'runout' }` end, sharing the end angle with chamfers): the in-place Ends row chamfers an end the thread reaches and runs out an end where it stops short, and a chamfer on a stopped-short end is still refused by code with copy that points to the runout. New profiles `'npt'` (ASME B1.20.1, 60°, 0.8P deep, 0.038P flats) and `'bspt'` (ISO 7-1 R on a boss / Rc in a bore, 55°, 0.640327P deep, its rounded crests and roots approximated by P/6 flats, which an advisory says) cut a 1:16 taper through the kernel's `taper` spec. `pipeSize` takes 1/8″–2″ from each standard's table (`packages/shared/src/pipe-threads.ts`), or the size the face is nearest. The fitting end is the end the thread starts at: a boss tapers small there and is gauged L1 (NPT) or the gauge length (R) in, and a bore opens large there and is gauged on its face (NPT) or half a pitch behind it (Rc), all measured from the fitting face, so an offset moves the band and never the gauge plane. The length is the standard's (NPT L2, BSPT minimum useful thread), within the face and stopping where the crest meets the cylinder, with an advisory whenever the band ends there short of the standard (a stored default length included); an offset that leaves no length is refused in plain language. Printed-fit clearance starts at Exact for pipe threads. Parallel Rp/NPS are not covered. Plain-language copy for `thread:ends-overlap` and `thread:taper-out-of-range` (and for the taper's own `cylinder-too-small`, `bore-too-large` and `too-deep`). The build refuses a kernel that does not report the runout (`details.geometry.start|end.kind`) or the taper (`taperAngle`) it was asked for, and names a thread face from `details.faceRoles` (`thread.face.<role>`) only where a role holds exactly one face (ADR-013). Older documents load unchanged; a runout or pipe thread in a document that declares v56 or older is refused, on opening (saved partial patches included) and on writing. The panel settles each finished end by the build's own placement and snap (`threadSpanOnFace`, shared with the adapter): from the face length the kernel measured: a stored runout stays a runout unless an edit carries that end from short of the face onto its end, where it is chamfered, and every other end is a chamfer where the span reaches the face's end and a runout where it stops short, so it never writes a chamfer the build refuses. Evidence: `test/thread-pipe-runout.test.ts` (NPT and BSPT tables checked against their standards' relations; NPT 1/2 boss and bore, R and Rc 1/2 gauge planes, inch units and clearance; runout end specs; v56 documents opening unchanged and v57 content refused under v56; on the exact kernel a runout on a partial M6, the overlap refusal and 1/4-18 NPT on its pipe), `test/thread-feature.test.ts`, `apps/web/src/lib/inPlace/thread.test.ts` and `test/e2e/in-place-thread.spec.ts` (runouts stored where a dragged thread stops short).
