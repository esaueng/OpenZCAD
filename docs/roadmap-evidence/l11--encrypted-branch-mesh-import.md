Issue #1637, a 3MF imported into an encrypted revision branch: the branch is an encrypted account project the moment it opens, the mesh the feature rebuilds from is stored as an encrypted `mesh-payload` blob named by the branch's saved head, and nothing is sent on a plaintext route. A payload that cannot upload leaves the import landed and marked: the status says the mesh is saved locally, the save state reads Local source only instead of Saved, and File › Archive local sources (or Save) retries it; the retry stores the payload once, adds no geometry, and a second import of the same file names the blob the account already holds. The picked file is not kept by an encrypted project, which the import states as that rule and never as a failed upload (the wording from PR #1687); whether encrypted projects should store original mesh files stays an owner decision. No code change: PR #2276 stopped a branch opened straight after branching from being listed as this device's alone (which refused every archive there), and PRs #1687 and #1679 fixed the misleading message and the undo label. Regression evidence: `test/e2e/encrypted-content-blobs.spec.ts` (`@ci-smoke`), `apps/web/src/lib/importedMeshPayload.test.ts`.
