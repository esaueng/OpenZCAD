Offset Face and Offset Faces no longer commit a kernel result that carries a separate curved support with the moved face. On a box fused with an r6 boss whose seams with the front face and the top are rounded r1, the pinned kernel returned an exact, valid body with the boss translated by the offset; the adapter now refuses it with the typed `offset_face_carried_detached_support` reason through both the drag preview and the commit rebuild, and the boss stays where its feature placed it (`exact-offset-face-detached-carry.test.ts`, `test/parity/offset-face-detached-boss.spec.ts`). The same defect had been recorded as qualified at four K10 part A chain steps, whose post moved with the plate's front or left face; they are now pinned to the refusal (`offset-carries-post` in `test/direct-edit-corpus/pins.ts`). Only the moved face's own blend chain may ride along: rounds tangent to it, then same-radius blend-shaped faces tangent to those, so a bore or boss never qualifies whatever its radius. The guard's tolerances follow the body's size and the move, not the distance from the origin, so an R6 bore beside an r6 boss and a model 60 km from the origin both still refuse.
