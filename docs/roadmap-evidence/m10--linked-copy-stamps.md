Linked copies and repeated stamps (schema v137, up from v136; no kernel change). A transform copy can store `stampBodyIds`: each id names one more copy, stamped by the same transform from the copy before it, so stamp k lands where the transform applied k times puts the source (rotations about the stored pivot included), each through the same verified-lineage copy, so its edges stay addressable. Linked, the stamps are one History step owning every copy ("× 3 copies"); an edit to its transform moves every stamp, and the stamps are body wiring, never patchable. As separate steps, each stamp is its own transform copy of the one before. Either way one Done is one transaction and one Undo removes every stamp. The Move bar's Options gain Copies (1–50, while Keep original is on) and "Link copies (one History step)"; the viewport previews every stamp before Done. History Duplicate stamps as many new bodies. A content gate refuses stamps in a document or replayed command that declares v136 or older. Evidence: `test/transform-copy-stamps.test.ts` (closed-form bounds and volumes for three stamps along X and for 90°, 180° and 270° turns about the pivot, four STEP solids, undo/redo/replay under the same BodyIds, an edited step moving every stamp, a fillet on one stamp leaving the rest, separate steps landing where linked stamps land, Duplicate, count refusals and the v137 gate), `moveCopyPreview.test.ts`, `DirectModelingOverlays.test.tsx`, `featureSummary.test.ts` and the Chromium smoke case "the Move card stamps linked copies or separate steps" in `test/e2e/transform-copy.spec.ts`.
