# OpenZCAD design review — 1 October 2026

**Site reviewed:** https://zcad.app, signed out, local projects only, nothing shared.

**Deployed commit:** the review began on `378ef670` (`/build-meta.json`: Remus 2026.1.21, kernel commit `4a93e758`). A production deploy landed mid-session: from step 5 onward, and for every width and theme recheck, the site served `d1a7c32c` (PR #498, Remus 2026.1.23, kernel commit `eac9317c`). Both commits are named per finding where it matters; the kernel-dependent fillet refusal was re-checked on both and behaves the same.

**Goal judged against:** "An easy to use, simple yet powerful, intuitive, web-based CAD program."

**How it was tested:** the Claude Browser pane at an emulated 1440×900, every layout finding re-checked at 1280×720 and 1024×768 in the light and dark themes. Four local projects: _Plate_ (step 1), _Bracket_ (step 2), _Errors_ (step 3) and the _Mounting Bracket_ demo (step 5). Each finding is marked **hands-on** (reproduced) or **suspected** (inferred). Everything the 3D view draws was screenshotted before it was judged.

**Harness caveats:** the pane runs hidden, so a screenshot is what forces a paint; two readings were corrected by re-screenshotting. Synthetic drags carry no intermediate pointer moves, so orbit by dragging could not be exercised (sketch rectangles, which only need start and end, drew fine); the orbit findings rest on the app's own shortcut reference. Downloads were not triggered (export verified up to its dialog). No trackpad was available.

## 2. A real part, counted — the mounting bracket

**What I built:** Box 80×40×5 (plate) → Box 80×5×40 (flange; both corner-origin, so they already touch along one edge) → Union → Fillet on the inside corner edge → two through holes → parameter `width = 80` referenced from both boxes and both hole positions (`width/2-15`, `-(width/2-15)`) → set `width = 120`.

| Tally                              | Count  | Notes                                                                                                                                                                                                                                                                                                                      |
| ---------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Clicks                             | **43** | plus 19 typed fields and 9 Enters                                                                                                                                                                                                                                                                                          |
| Fields retyped by hand             | 4      | every value I later wanted parametric had to be re-opened and retyped as an expression; no way to type `width` at creation and define it in place                                                                                                                                                                          |
| Camera moves I did not ask for     | 2      | auto-frame after the first box (welcome); the second box was created off-frame, so I had to press Fit; then I had to orbit (menu + cube corner) to reach the inside edge because it was hidden                                                                                                                             |
| Refusals or errors                 | 3      | fillet edge click missed with no feedback; `width = 120` refused ("No change applied · View details"); after suppressing the fillet both holes dropped to "needs repair · Hole target is unavailable"                                                                                                                      |
| Dead ends (undo, try another tool) | 3      | (1) Enter after picking both bodies from the Union list toggled the second body off instead of creating; (2) the parameter change was refused wholesale because the fillet's edge reference died — the reason sat in the activity log behind "View details"; (3) the workaround (suppress fillet) broke both holes instead |

**Result:** the bracket cannot be driven by its width parameter when built from primitives (hands-on, both commits). The same edit on the shipped Mounting Bracket demo — which places parts with explicit Move expressions and never uses Hole — works and moves everything. A first-time user cannot know the difference.

**How the same intent should feel, step by step, and the gap at each step**

1. _Plate:_ Box 80×40×5. Fine today. Gap: none.
2. _Flange:_ click the plate's back face → "Extrude" verb on the chip → drag up 40. Today: a second Box, hoping it lands where I want (it only did because both are corner-origin), then Union. Gap: no "push a face into a new wall" step; Union is a separate tool with a pick list.
3. _Inside fillet:_ click the edge → type 3 → done. Today: the edge was hidden behind the flange from the default view; the first click missed with no feedback; two chips plus a card opened. Gap: silent miss, duplicated feedback.
4. _Holes:_ click the top face twice at the spots I want. Today: a card with U/V numbers whose directions are unknown and no ghost. Gap: no preview, no axis names, two Enters.
5. _Width parameter:_ type `width` into the box's Width field at creation; the app offers "Define width = 80". Today: add the parameter in a separate panel, then re-open four features and retype. Gap: four re-entries.
6. _Change width:_ type 120, everything follows. Today: refused, then broken. Gap: references die on resize.

Removing steps beats adding features here: steps 2, 5 and 6 each remove a whole tool visit.

## 6. Visual consistency — breaks in the system (each cites two places that disagree)

- **Card headers:** Box/Hole/Union/Mirror use a title + grey eyebrow "NEW FEATURE"; Extrude uses a chip header "Extrude · Ready · Drag the region to pull it into a solid."; Fillet-on-pick shows a chip **and** a card; Move uses "DIRECT EDIT". Same kind of control, three looks.
- **Field labels:** Move creation card says "dX / rX"; the same feature's edit card says "Move X / Rotate X° / Scale ×".
- **Apply behaviour:** Box edit card stays open after Apply ("Edited Box. +2"); Hole edit card closes after Apply; Hole needs an extra "Edit hole" click before its fields appear, Box does not.
- **Primary button text to assistive tech:** every Create/Apply button is announced as "Enter" (the kbd hint is its accessible name); the Export dialog's format radios are announced as "on".
- **Face names:** the Hole list says "Top face (1)" in one pass and "Top face (2)" for the same face in the next, and reorders between passes; the body stays "Box Body" after Union; the Union list shows two rows both named "Box Body".
- **Overlaps:** the sketch-plane chooser sits under the View/Tweak/Build toggle (1440, 1280) and under the project name with its × hidden (1024), light and dark; the section popover sits on top of the Shell/Mirror/Pattern cards; the selection callout is clipped by the right column at 1024.
- **Truncation:** "Circular patt…" in the fold at 1440; "Place mou…" card title; "mount_inse" in a field; "17 features · at Wall to…" in the collapsed History header.
- **Theme:** with the theme set to System under a light OS scheme, the start screen is light but the workspace chrome is dark (hands-on; Appearance help text says System follows the OS). Light chrome only appears when "Light" is chosen explicitly.
- **Menus:** the File menu does not close on Escape and stays open under the Export modal; the history row's "⋯" menu opens about 300 px away from its row when the panel is scrolled.
- **Empty states:** good and consistent ("No parts yet", "No features yet. Pick a tool from the command card to start.", "No archived imports or exports yet.").
- **Contrast:** fine in both themes except the lane message and "+n" counters, which are the smallest text on screen in the only place refusals are guaranteed to appear.

## 8. Input and accessibility

- **Keyboard-only:** the Box card's Tab order is Width → Depth → Height → Create → Cancel → the Parameters panel (Name sits before Width and is reachable with Shift-Tab). Enter creates in Box, Cylinder, Fillet; in Union it toggles the focused list row (F4); in Hole it first "checks" and then creates. Escape cancels a card when focus is inside it; from the Parameters panel it does nothing; outside a sketch one Escape clears everything (good). Arrow keys reorder a focused history handle. "?" could not be opened from the canvas (F24).
- **Shortcuts that exist but are not shown in the workspace:** Shift+left-drag orbit, right-drag pan, middle-drag (configurable), window/crossing select by drag direction, double-click fit, double-click edge for the chain, Space "normal to face", Q cycles the selection filter, 1–4 views, W display mode, P projection. They are listed only in Settings → Shortcuts.
- **Collisions with the browser:** ⌘S is intercepted (creates a "Manual save" revision, no browser dialog); ⌘K opens the command box; ⌘, opens settings. All deliberate and working.
- **Enter / Escape meaning:** Enter means "create" in six commands, "check then create" in Hole, "toggle the row" in Union after a list pick, and "commit the field" in the parameters panel. Escape means "cancel" in cards, "clear selection" outside, "stop the line chain" in a sketch, nothing in menus.
- **Screen readers:** refusals reach a `role="status"` live region (the lane) — readable; the red card banners are not live regions. Create/Apply buttons are named "Enter"; export radios "on"; the "Check watertightness" button and the body-list rows in Union have no accessible name; twelve constraint tooltips "Draw an entity first." sit in the tree.
- **Pointer targets under 24 px (hands-on count: 36):** history-row icons 20×20 and reorder handles 14×12, the timeline slider thumb 20×8, orientation-cube corner buttons 10×17 and 20×6, section headers 14 px tall, "Rename project" 17 px.
- **Orbit, pan, zoom:** mouse wheel zooms toward the pointer (confirmed); orbit is Shift+left-drag and pan is right-drag per the app's reference (not exercised, see caveats); plain left-drag on empty canvas is a selection box that gives no feedback when it catches nothing (hands-on). Trackpad: not available; the Viewport settings say two-finger pan and pinch zoom with automatic detection.

## Findings — one per root cause

Format: **Where** · **What** (user's words) · **Why it matters** (goal, who) · **Severity** · **Fix** · **Evidence**.

**F1 · Parameters cannot resize a primitive-built part.** Bracket project, Parameters panel, `width` 80 → 120 after Box+Box+Union+Fillet+Hole+Hole. "I made one number drive the part and the app threw the whole change away; when I worked around it, my holes vanished." Powerful, intuitive; first-time and regular. **Blocker.** Fix: when a rebuild loses a face or edge reference, re-resolve it through verified lineage/witness correspondence — accept a match only when it is unique, and keep refusing on zero or ambiguous matches (ADR-011 forbids a nearby or positional substitute, and `resolveDirectEditFaceInSolids` already refuses ambiguity; a nearest-centre guess would silently move a feature on a repeated or symmetric part); show the refusing feature's sentence under the parameter row instead of behind "View details". Alternative with lower cost: refuse before the user builds the dependency ("Holes on a unioned body will not follow a width change") — honest but it concedes the promise. Hands-on, both commits.

**F2 · Deleting a feature with dependents does nothing, silently.** Bracket, Box 1 selected; Del key, card "⋯ → Delete feature", history row "⋯ → Delete". "I pressed delete three different ways and nothing happened." Intuitive, easy; first-time. **Blocker** (a user cannot tell whether the app is broken). Fix: the card already knows "Affects 2 later features"; show a confirm listing them with Delete/Cancel, then delete and toast with Undo. Hands-on.

**F3 · Hole position has no preview and unnamed axes.** Hole card, "Position on face (from centre) U V". "I typed −40 on a 100 mm plate and was told the hole misses the body." Easy, intuitive; first-time. **Major.** Fix: draw a ghost cylinder at the current U/V while the card is open, and label the fields with the face's axis names ("Along X", "Along Y"); let the face click set the position under the cursor. Hands-on.

**F4 · Enter toggles the last picked list row instead of creating.** Union card after clicking both bodies in the list; lane says "Enter creates". "It un-picked my body when I pressed Enter." Intuitive; first-time and keyboard users. **Major.** Fix: list rows must not be the form's submit target; handle Enter at the card level. Hands-on.

**F5 · Stale command state leaks between projects and past commits.** "Fillet · Ready" chip and the lane text "Drag the handle to set the fillet on edge…" shown in a brand-new empty project; the same chip stays after a fillet is applied. "There's a fillet thing on screen and I have no body." Simple; first-time. **Major.** Fix: reset interaction state on project open and on command commit. Hands-on.

**F6 · A deploy breaks the open tab.** Start screen, "Open demo" after production moved from 378ef670 to d1a7c32c: footer text "Failed to fetch dynamically imported module: …/demos-BLYQ4WoN.js"; the old hashed URL now returns the SPA HTML with HTTP 200. "I clicked the demo and nothing happened except small grey text at the bottom." Easy; everyone with a tab open during a release. **Major.** Fix: catch the dynamic-import failure and show "A new version is available — reload to continue" with a button; keep the previous asset generation served for a day. Hands-on.

**F7 · Fillet refusal suggests a radius smaller than the one that works, and the preview lies.** Plate (6 mm) and demo wall (8 mm), radius 5 requested, 3 current: "radius 2.5 builds here"; the handle showed "R 5 mm" as a clean preview. "It told me to go below what I already had." Intuitive; first-time. **Major.** Fix: bisect between the current radius and the requested one; mark the preview as unverified or run the check on handle release. Hands-on, both commits.

**F8 · Selection is drawn duller than non-selection.** Any history-row click or face pick: the selected faces go grey-tan, the rest keeps its gold/orange feature colour. "The highlighted bit is the one that looks switched off." Intuitive; first-time. **Major** (design question on palette). Fix: selected = accent outline plus a brighter tint; the rest dims. Hands-on (screenshots: Box 1 selected highlights the flange brighter than the plate).

## Top five changes to make next

1. Make references survive a resize, or refuse before the user depends on them (F1), and surface the reason inline (not "View details").
2. Never go silent: dependent delete gets a confirm with Undo; disabled Create gets a sentence; a missed edge click gets a lane line (F2, F17, F12).
3. Give Hole a ghost preview and named axes, and collapse its two-step into one Create (F3, F14).
4. One card, one chip, one height rule: the card owns the column height and scrolls; the floating callout alone carries verbs; the sketch-plane chooser moves under the top bar; the section popover moves to the lane (F9, F10, F11).
5. Invert the selection tint so the selected thing is the bright one (F8).

## What is already good — protect these

- **Refusals that teach:** the Union gap message (names the gap in mm and says what to do) and the reorder message are models for every other error.
- **Expressions everywhere, with a live readout:** typing `width` into any field shows "= 80" immediately; the demo's nine parameters drive the whole part.
- **Nothing is ever lost:** autosave, instant reopen, labelled undo/redo through renames and suppressions, a revisions list with Restore and Branch, and ⌘S intercepted into a named revision.
- **The command palette and File menu use plain words**, group by intent, and show the key for everything that has one.
- **Dependency awareness in the card:** "Affects 6 later features: Union L bracket, …" is exactly what a user needs before deleting or suppressing — it only needs to be used at the moment of deletion.

## Does it read as a simple, powerful, intuitive CAD tool today?

It reads as a powerful tool with a simple surface and an intuitive first minute: a plate with holes and a fillet in six minutes with no help is better than most desktop CAD manages, and the quiet dark stage, the eight-tool rail and the plain-English palette are genuinely simple. The intuition breaks the moment the user leans on the parametric promise or hits a limit: a width parameter that destroys the part it was meant to drive, a delete that does nothing, a hole whose position fields point along an unnamed axis, and refusals that sit below the fold. The single change that would move it most is to make the app never fail silently — every disabled button, missed click, refused parameter and blocked delete says one sentence in the lane with the next action — because almost every blocker here is a case where the engine knew exactly what was wrong and the interface did not say.
