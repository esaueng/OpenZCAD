# Remus kernel growth attribution, 2026-09-04 to 2026-10-12

This appendix to [the kernel WASM size policy](kernel-wasm-size-policy.md#ceiling-change-2026-10-step-1)
attributes every byte of the kernel's growth from the first package after the translator split
(Remus `3ec7132803`, 2026-09-04, 7,602,120 raw bytes) to the 2026-10-12 package `remus-wasm`
2026.1.55 (Remus `259683c5ec`, 10,479,386 raw bytes): **+2,877,266 bytes**.

## Method

- Every Remus `main` first-parent commit that changed `crates/wasm/pkg/remus_wasm_bg.wasm` is a package
  refresh; `git ls-tree -l` gives its raw size. There are 107 in the window, so 106 consecutive pairs.
- Each pair's delta belongs to the source commits between the two packages' build sources: the
  `from <sha>` (or `wasm-refresh-<sha>`) named in the refresh subject when `main` contains it,
  otherwise the refresh commit itself (feature and integration PRs that carry their own package).
  The window is `git log --first-parent <previous source>..<source>`.
- Deltas telescope, so the rows sum exactly to the net growth. A window that contains only the
  refresh itself is a rebuild that caught up with code merged in the window before it, and is
  grouped with that window.
- A window holding several PRs cannot be split without rebuilding each PR, so the whole window
  goes to the capability that dominates it; the window's PRs are listed below so the grouping can
  be checked.

## After the window

kernel from 10,481,536 bytes (2026.1.56) to 9,412,128 bytes (2026.1.57, Remus `16371d5912`):
−1,069,408 raw bytes, about 37% of the growth above.
