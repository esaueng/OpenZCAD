# F06 row switch against the W01 budgets (2026-11-17)

[F06](../../ROADMAP.md#f06) requires switching configuration rows to rebuild
within the [W01](../../ROADMAP.md#w01) budgets. This record measures Switch →
frame for a row change beside W01's own Apply → frame, in the same session,
on the W01 fixtures and against the budgets in `scripts/active1-budgets.mjs`.

## Result

Three quiet-host rounds of 30 samples each, medians of the round medians
(range across rounds), in milliseconds:

| Measurement                                 | Median (range) | Budget |      p95 (range) | Budget |
| ------------------------------------------- | -------------: | -----: | ---------------: | -----: |
| W01 Apply → frame, simple box               |     39 (39–40) |     60 |       43 (43–51) |    100 |
| W01 Apply → frame, 100-feature history      |  125 (123–127) |    150 |    149 (146–149) |    170 |
| **F06 Switch → frame, simple box**          | **42 (40–42)** |     60 |   **48 (47–60)** |    100 |
| **F06 Switch → frame, 100-feature history** | **87 (87–92)** |    150 | **116 (98–119)** |    170 |

The row switches' medians and p95s meet the W01 budgets on both fixtures,
as W01's own figures are judged (the medians of each round's median and p95;
no budget is stated for single samples). The 100-feature switch's median is
also inside W01's 100 ms screen target; its p95 is not. A switch rebuilds less
than the W01 edit there because the isolated part's history is the only one
the row's parameter reaches (the other 99 parts are switched off), so the
switch measures one dependent rebuild and its frame.

The W01 figures are close to the 2026-11-15 baselines (38/42 and 121/132
ms); the 100-feature p95 ran higher here, so if anything this host was a
little noisier than the one those budgets were set on.

## Method

`test/e2e/perf-configuration-switch.spec.ts` (run only with `OZ_PERF=1`)
opens W01's fixtures with a variant table over the first box's width: the
simple box, or a 100-feature history with the other parts switched off
(W01's isolated part). Row 0 is active; rows 1–30 each have a width no build
has used (30.5 mm, 31 mm, …), as W01's edits use unique values, so no switch
is served from the rebuild cache. A sample runs from the click on the row's
radio to the end of the `oz:edit.frame` measure of the revision that switch
committed — the same mark W01 reads — and each switch is checked to have
reached the row before the next.

Host: AMD Ryzen 5 5600, Radeon RX 6600, Vulkan ANGLE, production renderer;
1-minute load 2.0 and 6.9 GB available at the start; the script waits for a
quiet host before every round.

## Reproduce

```bash
node scripts/measure-active1-baselines.mjs --runs 3 --angle vulkan \
  --only w01-box,w01-history,f06-switch-box,f06-switch-history --check
```

On a machine shared by several agent lanes, pass
`--heavy-lock ~/.cache/openzcad-heavy.lock`: each round then takes that lock
only for its own run (`flock -n`) and, when another lane holds it, waits
outside the lock and retries, so the probe never holds the lock while it
waits. The quiet-host check (`scripts/perf-host.mjs`, `busyRows`) no longer
counts jobs merely queued behind that lock: a waiting `flock` and the shells
above it load nothing, and counting them made a probe holding the lock wait on
its own queue.
