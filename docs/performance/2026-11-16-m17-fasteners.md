# M17 fasteners against the H02/W01 budgets (2026-11-16)

[ROADMAP](../../ROADMAP.md) [M17](../../ROADMAP.md#m17) asks that standard
parts be "drawn with a simplified thread display so many fasteners stay
within rendering budgets". This record measures about 100 fasteners against
the [Active 1 budgets](2026-11-15-active1-baselines.md) on the same machine.
The W01 budget for an edit in a 100-feature history is Apply → frame
**150 ms median, 170 ms p95**. The H02 budgets for the first edit after a
settled reload are **400 ms and 850 ms**. Every run's figures are in the
[provenance](2026-11-16-m17-fasteners.provenance.json).

| 100 ISO M6 × 20 socket screws (and a box), browser                       | Measured (median of runs) | Budget          |
| ------------------------------------------------------------------------- | ------------------------: | --------------: |
| W01 Apply → frame, editing the box before them (median / p95), simplified |           **142.7 / 163.5** | 150 / 170 ms    |
| H02 first edit after a settled reload, simplified                         |                **163.9**  | 400 / 850 ms    |
| Reload → exact ready, simplified                                          |                     1,359 | (see below)     |
| The same 100-feature history of boxes (reference), Apply → frame          |             130.4 / 150.6 | 150 / 170 ms    |

**Modeled threads are far outside any budget**, which is why Simplified is
the Standard part tool's default. A modeled M6 × 20 screw is about 465,600
display triangles and 8.4 MB of mesh. Ten of them take 17 s to build cold,
and 100 would be about 46.6 M triangles and 840 MB of mesh. That was not run
in a browser tab on this shared machine. A simplified screw is 836 triangles.

## What made it fit

The first measurement of 100 simplified screws was about 190 ms Apply →
frame, with the worker at 93 ms. Three changes in this slice brought it
inside the budget:

1. **The simplified part is its plain envelope.** It keeps its head's form
   (socket, hex or countersunk), every size and its length. It has no
   thread, drive recess or chamfer: a socket screw is one revolve with 5
   faces and 6 edges, not 14 and 28. Edge polylines dominated each part's
   topology (27 of 40 KB). Each sync result carries them, the worker clones
   and posts them, and the viewer compares and draws them for all 100 parts
   on every edit. 100 parts now carry 2.1 MB of topology instead of 4.8 MB,
   and they build cold in 0.36–0.65 s instead of 1.7 s (Node).
2. **Unchanged standard parts are reused, not rebuilt.** A standard part on
   a plane reads no other body. Like a primitive, the history cache's
   primitive reuse (`exact-primitive-cache.ts`) now restores it with its
   derived lengths when an unrelated edit leaves its digest unchanged. A
   part in a hole is still rebuilt, because it reads the hole's body. An
   edit of the box before 100 parts went from rebuilding 100 parts (about
   1.7 s) to replaying one feature (`independent-reuse`, `replayed: 1`): the
   adapter answers in 10–12 ms (Node).
3. **A nut's** simplified form is a plain hex prism with its bore (no
   chamfer intersection), and an insert's is its plain tube (no knurl).

The rest of the edit is the app's, not the parts'. The worker took 54 ms
against 48 ms for 100 boxes, and the main thread 85 ms against 80 ms. A
validated edit's result posts every body, cloned, so the main thread reads
all of them again. That path is shared with every other feature kind.

## Results

Medians of each run's 30 samples, then the median across runs, in ms. Host:
the [Active 1 machine](2026-11-15-active1-baselines.md#machine-and-build)
(Ryzen 5 5600, Radeon RX 6600 through Vulkan ANGLE, Chromium 156), Remus
2026.1.141. The production renderer was built with `VITE_E2E=1
VITE_E2E_FULL_RENDER=1` and served by `vite preview`.

| Stage, median of run medians       | 100 simplified screws | 100 boxes (reference) |
| ---------------------------------- | --------------------: | --------------------: |
| Request → worker response          |                  53.9 |                  47.8 |
| Response → bodies installed        |                  35.9 |                  32.1 |
| Installed → next frame             |                  49.3 |                  48.0 |
| **Input → frame, median**          |     **142.7** (141.6–148.8) |   **130.4** (125.7–135.0) |
| **Input → frame, p95**             |     **163.5** (156.9–185.1) |   **150.6** (136.7–164.5) |
| First edit after a settled reload  |       163.9 (161.4–170.1) |   157.6 (136.1–179.1) |
| Reload → exact ready               |   1,359 (1,328–1,504) |         691 (611–772) |

A **quiet host** means each run started with a 1-minute load below 2.0, at
least 3 GiB available and no other cargo, rustc or Playwright process. The
loads were 1.02–1.60. The third fastener run ended at load 2.5, and its p95
is the high end above. A third box run hit the same load rise and timed out
after reload, so it is excluded. Two box runs, interleaved with the fastener
runs, are the reference.

**Reload → exact ready** is about twice the boxes' because the reload builds
100 small revolved solids cold. The H02 budgets were set for the drilled and
lettered holders (1.0 s and 0.7 s to ready). There is no H02 budget for a
100-part project, so this is recorded rather than judged. The H02 measure the
row names, the first edit after reload, is inside its budget.

## Reproduce

```bash
pnpm install --frozen-lockfile
VITE_E2E=1 VITE_E2E_FULL_RENDER=1 pnpm --filter @openzcad/web build
pnpm --filter @openzcad/web preview --host 127.0.0.1 --port 4792 &
# Repeat each on a quiet host; the box run is the 100-feature reference.
OZ_PERF=1 OZ_PERF_ANGLE=vulkan PLAYWRIGHT_PORT=4792 \
  CAD_PERF_BROWSER_SAMPLES=30 CAD_PERF_BROWSER_FASTENERS=100 \
  CAD_PERF_BROWSER_OUT=fasteners.json \
  pnpm exec playwright test test/e2e/perf-cad-edit.spec.ts --workers=1
OZ_PERF=1 OZ_PERF_ANGLE=vulkan PLAYWRIGHT_PORT=4792 \
  CAD_PERF_BROWSER_SAMPLES=30 CAD_PERF_BROWSER_HISTORY=100 \
  CAD_PERF_BROWSER_ISOLATE=1 CAD_PERF_BROWSER_RELOAD=1 \
  CAD_PERF_BROWSER_OUT=boxes.json \
  pnpm exec playwright test test/e2e/perf-cad-edit.spec.ts --workers=1
# The adapter alone: cold build, edits, sizes, kernel time, an optional
# CPU profile of the timed edit.
FASTENER_PERF_RUN=1 FASTENER_PERF_COUNT=100 \
  pnpm exec vitest run --config test/perf/standard-parts-display.config.ts
```

The fixture (`test/support/fastener-grid.ts`) is a box and then
`CAD_PERF_BROWSER_FASTENERS` ISO M6 × 20 socket head cap screws, 15 mm apart
on a square grid. The probe edits the box's width, which comes first in
History, so every screw after it is either rebuilt or reused.
`CAD_PERF_BROWSER_THREADS=modeled` draws them modeled. With fasteners, or
with `CAD_PERF_BROWSER_RELOAD=1`, the probe then reloads once the last edit
is saved on the device. It times the reload to the worker's own `ready`
state and the first edit after it. A `.cpuprofile` path in
`CAD_PERF_BROWSER_PROFILE` keeps the main-thread profile. None of this runs
in CI.
