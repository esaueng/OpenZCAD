The viewer rail, five ways

Today the rail is a 143 px labelled panel wedged under the orientation cube, and it reads like a settings list instead of a control surface. Every option below moves it to a compact vertical strip on the right edge, centred. They differ in one decision: how much text survives, and where the standard views go. Every number on this page was measured off the specimen beside it, not estimated.

Forces every hover/expanded state on, so you can read the options without a mouse.

  • Compact where it matters — at rest, over the model — and fully self-describing the moment you reach for it.
  • Keyboard users get the same reveal through :focus-within; no tooltip dependency.

Decision

C shipped. The rail is now four state toggles and a views flyout, centred on the right edge at 36 × 157 — a 73% cut in footprint, with the orientation cube keeping navigation and the flyout adding Back, Left and Bottom, which never had buttons before.

Its one real weakness — no state visible at rest — is answered in the display-mode control, which now draws the mode: a lit cube with its edges, a lit cube alone, and an all-edges cube with the hidden three ghosted. The eye icon it replaces was identical across two of the three modes.

B remains the alternative if hover-reveal is ever wanted: 36 px at rest, 142 px open, with the collapsed view row doubling as a current-view readout.

Specimens render at 1∶1 CSS pixels against #070b10, using the app’s live tokens — --color-surface, --color-accent, --radius-sm — and the same Lucide icon set at 15 px. Sandboxed pages can’t load IBM Plex, so type falls back to the stack tokens.css already declares behind it.
