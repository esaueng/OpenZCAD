## Where we are

OpenZCAD has a working browser CAD foundation: exact solid modeling, editable
feature history, expressions, direct manipulation, local persistence, optional
cloud sync and collaboration. The largest remaining product gaps are complete
sketch constraint workflows, reference geometry, drawings and assemblies.
Recent work improved existing modeling and the bounded imported-holder workflow,
and the 14 September kernel-adoption wave (#330–#342) moved booleans, patterns,
blends, mesh import, sketch modify tools and sections onto typed kernel entry
points; it did not complete those larger milestones.

**Status vocabulary:** `Open` means a defined remainder; `Partial` means a
bounded subset is delivered; `Revalidate` means the older finding lacks current
proof and must be reproduced before implementation; `Deferred` means deliberately
outside the next delivery sequence. No feature row below is claimed actively
owned without a linked open implementation PR. “Delivered” means merged source
with referenced evidence; production acceptance is recorded separately.

## Delivery order

Finish useful workflows before adding a second way to do the same action.
Use the ordered product milestones below; kernel/reliability work runs alongside
only where dependencies and touched files are disjoint. Each row is an outcome,
not necessarily one PR. Split a large row into named, bounded slices under the
same ID before coding; never treat a partial slice as the whole row's completion.

| Order | Milestone                            | Exit signal                                                                                                                                                                       |
| ----- | ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0     | Close the shipped workflow gaps      | H01 has an explicit acceptance matrix; H02 has measured cold/warm behavior; U01/U02 resolve reproduced command/value/feedback disagreements; L01 records outstanding live checks. |
| 1     | Complete the modeling foundation     | S01–S06, R01 and F01–F04 meet their row contracts: durable dimensions, understandable constraints, editable sketch geometry and useful reference/parameter surfaces.              |
| 2     | Deepen part modeling and inspection  | Selected M01–M09 and I01 slices work through creation, revision and export with their kernel prerequisites proved.                                                                |
| 3     | Drawings MVP                         | D01 then D02; D03/D04 add sections and DXF. A user can produce a scaled, dimensioned shop handoff from a saved model.                                                             |
| 4     | Assemblies MVP                       | AS01 then AS02/AS03; AS04/AS05 follow only when their query, exchange and reference dependencies qualify.                                                                         |
| Later | Reach, automation and new body types | Select L02–L07, D05 or K09 from a measured use case; do not expand every lane at once.                                                                                            |

## Completion and maintenance rules

1. Refresh main, the pinned kernel and open PR ownership before selecting a
   master ID. Use a new isolated branch; one bounded slice and one ready PR.
   A stacked PR names its dependency. Do not silently switch items when blocked:
   record the missing evidence/input against the selected row.
2. Before coding, record the slice, observable acceptance cases, dependencies
   and any schema/API/rollout decision. Preserve exactness/provenance, units,
   verified topology references, offline persistence and one-transaction undo.
   AI and manual edits use the same validated command path. Never weaken a
   refusal, oracle or tolerance to mark progress.
3. Run the root [AGENTS.md](AGENTS.md) verification gates and the row's browser,
   geometry or performance checks. Exact-head hosted checks are required before
   a merge decision; queued/skipped jobs are not passing. Deployment and manual
   Apple Silicon execution retain their separate authorization requirements.
4. Update this file in the implementation PR: status, shipped subset, evidence
   (tests plus PR/commit), remaining acceptance and changed dependencies. Add a
   linked child ID for a split, never a second untracked plan. Keep detailed
   acceptance specifications linked; do not copy their status tables back here
   as multiple competing versions.
5. Close only the scope proved. Move completed rows into the delivered baseline
   with their stable IDs, or retain a short completion row so links survive.
   Record live acceptance separately from merged source. Revalidate old kernel
   claims upstream and old UI findings on the rendered current app before work.
